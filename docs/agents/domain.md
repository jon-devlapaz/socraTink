# Domain Docs

Socratink currently uses a single bounded context.

Before exploring or changing the system, read:

- root `CONTEXT.md`, when present;
- relevant decisions under `docs/adr/`, when present.

If they do not exist, proceed silently. Create them lazily through domain modeling when vocabulary or a durable architectural trade-off is actually resolved.

Use canonical terms from `CONTEXT.md` in issue titles, specifications, tests, and code. Surface conflicts with existing ADRs rather than silently overriding them.
